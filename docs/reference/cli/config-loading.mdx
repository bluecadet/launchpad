The Launchpad CLI finds and loads your project config file automatically.

## Config file search

The CLI looks for these file names, in order:

1. `launchpad.config.js`
2. `launchpad.config.mjs`
3. `launchpad.config.ts`
4. `launchpad.config.cjs`
5. `launchpad.config.mts`
6. `launchpad.config.cts`

The search starts in the current working directory and walks up parent directories, up to 64 levels, until it finds a config file.

## Config file format

### JavaScript/TypeScript config (recommended)

```js
import { defineConfig } from '@bluecadet/launchpad/cli';

export default defineConfig({
  plugins: [
    // Your plugin configurations here
  ]
});
```

## Configuration structure

<ConfigReference id="launchpad-options" />

The top-level config sets controller options, plugins, and named workflows. See [Controller configuration](/reference/controller/#configuration) and [Host-owned workflows](/reference/controller/#host-owned-workflows).

Each plugin factory takes its own configuration:

- `content()`: content management settings ([content config reference](/reference/content/content-config/))
- `monitor()`: process monitoring settings ([monitor config reference](/reference/monitor/monitor-config/))

### Configuration reference conventions

Configuration references render from the runtime Zod schemas. Pages with per-property sections embed each property's schema metadata under a written heading, followed by prose describing its behavior. Generated descendant definitions and full fallback property lists keep their schema summaries.

**Input default** is the value `.default()` or `.prefault()` supplies when a field is omitted. A prefault passes through validation and transforms, so the resolved value can differ. The surrounding prose covers defaults that transforms or runtime setup fill in. For example, a transform resolves the scheduler retry policy, and setup adds the observability resource identity.

Requiredness reflects the schema structure, including optional fields and defaults. Union branches can have different requirements. Cross-field rules still apply: a scheduler job needs exactly one of `interval` and `cron`, though each field is optional on its own. The renderer can't infer conditional requiredness or refinement rules, so check the property notes and validation constraints.

## Environment variables

Config files can read environment variables from `process.env`. See [Environment variables](/reference/cli/env/) for loading them.

## Type safety

In TypeScript, or an editor with TypeScript support such as VS Code, `defineConfig` provides:

- IntelliSense for every configuration option
- Type checking for configuration values
- Autocompletion
- Inline documentation

## Example

```js
import { defineConfig } from '@bluecadet/launchpad/cli';
import { content } from '@bluecadet/launchpad/content';
import { monitor } from '@bluecadet/launchpad/monitor';
import { jsonSource } from '@bluecadet/launchpad/content/sources/json';

export default defineConfig({
  plugins: [
    content({
      sources: [
        jsonSource({
          id: "api-data",
          files: {
            "data.json": process.env.API_ENDPOINT
          }
        })
      ],
      downloadPath: "./content"
    }),
    monitor({
      apps: [
        {
          pm2: {
            name: "exhibit-app",
            script: "./app.exe"
          }
        }
      ]
    })
  ],
});
```
