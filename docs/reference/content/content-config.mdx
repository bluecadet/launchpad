Options for content sources, transforms, and file handling.

## Options

Input defaults come from the schema and apply before transforms and runtime setup. See [configuration reference conventions](/reference/cli/config-loading/#configuration-reference-conventions).

### `sources`

<ConfigReference id="content-options" property="sources" />

The sources to download content from. You can mix source types. Each item accepts `ContentSource | Promise<ContentSource>`: a source object or a Promise that resolves to one.

See the [sources reference](/reference/content/sources/) for per-source options.

```typescript
content({
  sources: [
    defineSource({
      id: 'installation',
      fetch: () => ({ id: 'settings', data: fetchSettings() }),
    }),
  ],
});
```

#### `ContentSource`

Each item has these fields once its Promise, if any, resolves. Field names are relative to one `sources[]` item.

### `transforms`

<ConfigReference id="content-options" property="transforms" />

Transforms that modify, analyze, or enhance content after download and before publication.

See the [transforms reference](/reference/content/transforms/) for available transforms.

### `downloadPath`

<ConfigReference id="content-options" property="downloadPath" />

Directory where Launchpad publishes promoted content. A fetch run writes to an isolated staged directory and replaces the published source directory only after the run succeeds.

Accepts an absolute path or a path relative to the launchpad config directory.

### `tempPath`

<ConfigReference id="content-options" property="tempPath" />

Directory for temporary files during content processing. Launchpad creates a staged workspace here for each run and removes it when the run completes.

Accepts an absolute path or a path relative to the launchpad config directory.

### `backupPath`

<ConfigReference id="content-options" property="backupPath" />

Directory for backups of published content taken before new downloads. Backups support compatibility and recovery flows; ordinary fetch failures need none, because Launchpad never promotes failed staged output.

Accepts an absolute path or a path relative to the launchpad config directory.

### `keep`

<ConfigReference id="content-options" property="keep" />

Glob patterns for files to preserve when clearing directories.

Examples:

- `["*.json"]` keeps all JSON files.
- `["**/*.csv", "*.git*"]` keeps CSV files in any subdirectory and any Git-related files.

### `backupAndRestore`

<ConfigReference id="content-options" property="backupAndRestore" />

When enabled, Launchpad backs up published files before each fetch run and can restore them if promotion or recovery fails.

Ordinary fetch failures need no restore, because Launchpad discards staged output that was never promoted. The error state reports `restored: true` only when Launchpad restored at least one source from backup.

### `maxTimeout`

<ConfigReference id="content-options" property="maxTimeout" />

Network request timeout in milliseconds.

### `encodeChars`

<ConfigReference id="content-options" property="encodeChars" />

Special characters to encode in content and media file paths, so filenames stay valid on every platform.

### `versioning`

<ConfigReference id="content-options" property="versioning" />

Enables immutable versioned output. Pass `false` to disable it, `true` to enable it with the defaults below, or an object to enable it and override individual fields. The top-level input default is `false`, not a resolved settings object.

```typescript
content({
  versioning: { keepVersions: 5, ackTimeout: '20m' },
});
```

`keepVersions` must be a non-negative integer; Launchpad always keeps the active version and versions with fresh leases. `ackTimeout` accepts duration shorthand or milliseconds.

<ConfigFieldTable id="content-options" property="versioning" caption="Object fields (relative to versioning)" />

See [Versioning](/reference/content/versioning/) for defaults, publishing, retention, mode switching, and status output. Applications that read versioned content must follow the [version manifest](/reference/content/version-manifest/) contract.
