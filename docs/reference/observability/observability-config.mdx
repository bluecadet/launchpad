`observability()` accepts destination mode or legacy transport mode. Do not configure `destinations` and `transports` together.

## Destination mode

By default, destinations read the controller's canonical file. The controller owns the file directory and retention policy:

```typescript
export default defineConfig({
  controller: {
    logging: {
      dirname: '.logs',
      text: { enabled: true, level: 'info' },
    },
  },
  plugins: [
    observability({
      destinations: [destination],
    }),
  ],
});
```

Omitting `logStorage` is equivalent to `{ type: 'file' }`. Use `{ type: 'memory' }` to opt out of retained log delivery. The other destination options do not depend on the controller's file policy:

```typescript
observability({
  resource: { 'service.name': 'museum-kiosk' },
  destinations: [destination],
  include: ['log:*'],
  exclude: [],
  metrics: { intervalMs: 30_000 },
  delivery: {
    deliveryTimeoutMs: 5_000,
    shutdownTimeoutMs: 3_000,
    maxQueuedBatches: 50,
  },
});
```

Input defaults apply before transforms and runtime setup; for example, resource identity is supplied at runtime. See [configuration reference conventions](/reference/cli/config-loading/#configuration-reference-conventions).

### `resource`

<ConfigReference id="observability-destination-options" property="resource" includeChildren />

A flat set of resource attributes attached to every exported log and metric. The caller defines attribute names and meanings; Launchpad assigns no special meaning to client, project, installation, organization, or environment attributes.

Launchpad supplies only these defaults:

| Resource attribute | Default | Configuration behavior |
|---|---|---|
| `service.name` | `'launchpad'` | May be replaced with a nonblank string |
| `service.instance.id` | A runtime-generated UUID | Runtime-owned; configuring it is rejected |

The runtime generates a new `service.instance.id` during each plugin setup and adds no other attributes. An own `__proto__` key is rejected to prevent prototype-key data loss.

A resource can contain at most 64 configured attributes. Keys must be nonempty and at most 128 characters. String values are limited to 1,024 characters, and numbers must be finite. Nested objects, arrays, `null`, and `undefined` are not supported.

Resource attributes and metric-point attributes are separate scopes. Resource attributes are attached to every signal but not copied into metric points. Metric points keep their own bounded `attributes`, where only `service.name` and `service.instance.id` are reserved.

### `destinations`

<ConfigReference id="observability-destination-options" property="destinations" />

At least one destination is required. Each destination declares the exporters it supports. Names identify the delivery target in diagnostics and file-delivery checkpoints, so they must be nonblank and, after trimming, unique within the plugin.

The name `__proto__` is reserved because destination health is stored in ordinary objects, where that name would change the prototype and break state updates or serialization. Names such as `constructor`, `prototype`, and `toString` are allowed. Setup validates all names before any destination exporter factory runs.

### `logStorage`

<ConfigReference id="observability-destination-options" property="logStorage" includeChildren />

Selects the log delivery source. Omitted or `{ type: 'file' }` uses checkpointed delivery from the controller-owned canonical JSONL. `{ type: 'memory' }` uses bounded in-memory batching without replay, for tests, ephemeral delivery, or custom log exporters without replay support. Memory delivery does not disable controller logging.

File delivery is available only in destination mode and only for destinations with a log exporter. Legacy `transports` keep their in-memory path and reject both `{ type: 'file' }` and `{ type: 'memory' }`. The controller's logging config controls directory, format, rotation, and retention; `logStorage` accepts no directory, size, or age settings.

Each destination reads independently. A new destination starts at the oldest retained canonical record. After each acknowledged export, an atomic checkpoint records its progress. Restarting with the same destination `name`, credential-free `checkpointKey`, and controller log source resumes from that checkpoint. Built-in Loki and OTLP destinations derive the key from their normalized endpoint. Changing the name or endpoint starts a new reader at the oldest retained record. Rotating a token or headers keeps the existing checkpoint.

> [!WARNING]
> Enabling a destination can immediately export historical records and raise ingestion costs. Backends may reject records older than their accepted timestamp window. Check retained data and backend policy first. Bounded controller retention can expire unread records, and a lost acknowledgement can cause duplicate replay; delivery is neither lossless nor exactly once.

Memory delivery does not advance file checkpoints. Switching from memory to file resumes from the existing checkpoint, or from the oldest retained record if none exists, and may replay records already sent from memory.

Credentials are excluded from checkpoint identity, which matters for endpoints shared by multiple accounts, such as a common Grafana gateway. Change the destination name when switching accounts so the new account does not inherit the old account's delivery position.

File delivery preserves each record's original timestamp and resource snapshot. Custom log exporters must provide a stable `checkpointKey` and an `exportCanonical(batch, context)` method that honors the batch's historical resource snapshot, or use memory delivery. See [custom destination support](/reference/observability/custom-destinations/#file-delivery-support). An unavailable canonical file source never falls back to memory. Metrics are always latest, coalesced in-memory snapshots and are never reconstructed from the log.

### `include`

<ConfigReference id="observability-destination-options" property="include" />

Event-name patterns to export as logs. `*` is a wildcard. An empty array includes all available events.

In default file delivery, these filters select only [canonical records captured by the controller](/reference/controller/logging/#recorded-events), not every raw custom bus event. `include` cannot add unrecorded events to the canonical source; use memory delivery to capture custom events from the live bus.

### `exclude`

<ConfigReference id="observability-destination-options" property="exclude" />

Event-name patterns to suppress. Exclusions take precedence over inclusions.

`include` and `exclude` affect logs only. They do not enable, disable, or filter metrics.

### `batch`

<ConfigReference id="observability-destination-options" property="batch" includeChildren />

Controls how often logs flush and how many entries force a flush.

### `buffer`

<ConfigReference id="observability-destination-options" property="buffer" includeChildren />

In destination mode, `delivery.maxQueuedBatches` bounds each in-memory signal queue. Metric batches coalesce to the latest queued observation and are not retried. File-backed logs stay in the canonical log until their checkpoint advances or controller retention removes them; queue limits create no separate spool.

### `metrics`

<ConfigReference id="observability-destination-options" property="metrics" includeChildren />

Set `false` to disable gauge collection. `intervalMs` must be a positive integer no greater than `2_147_483_647`.

### `delivery`

<ConfigReference id="observability-destination-options" property="delivery" includeChildren />

All values must be positive integers. `maxQueuedBatches` cannot exceed 10,000.

### `transports`

<ConfigReference id="observability-destination-options" property="transports" />

For existing transport configurations, see [Legacy transport mode](#legacy-transport-mode).

## Legacy transport mode

<ConfigReference id="observability-legacy-options" />

```typescript
observability({
  transports: [createLokiTransport({ url: 'http://localhost:3100' })],
  include: ['log:*'],
});
```

Legacy mode is logs-only and keeps the existing in-memory batching, retry buffer, events, options, and plain-text Loki lines. It rejects the destination-mode options `resource`, `destinations`, `metrics`, `delivery`, and `logStorage`, including `logStorage` with `'file'` or `'memory'`, `metrics: false`, `metrics: {}`, and `delivery: {}`. Omit them entirely. See [Migrate from transports](/reference/observability/migration/) before switching an existing deployment.
